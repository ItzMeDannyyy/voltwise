# 3.2 Technology Requirements

## Software Requirements

### Operating Systems

| Component | Operating System |
|---|---|
| Backend server | Linux (Ubuntu 22.04 LTS recommended) / Windows / macOS (development) |
| Mobile client | Android 10+ / iOS 15+ (via Expo Go or standalone build) |
| Development workstation | Windows 10/11, macOS 12+, or Ubuntu 22.04+ |

---

### Web Server

| Item | Details |
|---|---|
| Framework | **Express 5** (ESM, TypeScript) |
| Runtime | **Node.js 20 LTS** or later |
| Transport | HTTP/JSON over LAN; CORS-enabled for cross-origin app access |
| Architecture | Modular — each feature has its own `routes → controller → service → dto` stack, aggregated under `/api` |

---

### Database Management System

| Item | Details |
|---|---|
| DBMS | **PostgreSQL 15+** |
| Database name | `voltwise_db` |
| ORM | **Prisma 7** (`@prisma/client`, `@prisma/adapter-pg`) |
| Driver | `pg` (node-postgres v8) |
| Schema | 7 tables (`User`, `Device`, `EnergyReading`, `Alert`, `Bill`, `Anomaly`, `PzemMetric`) + 2 enums (`DeviceStatus`, `AlertType`) |
| Migrations | Managed via `prisma migrate dev` |
| Seed | `prisma/seed.ts` — populates mock IoT sensor data for MVP demonstration |

---

### Development Tools

| Tool | Purpose |
|---|---|
| **VS Code** | Primary IDE for both backend and mobile development |
| **Prisma Studio** | GUI browser for inspecting and managing `voltwise_db` records |
| **Expo Go** | Mobile client for live-reloading the app on a physical device during development |
| **Postman / Thunder Client** | REST API testing and endpoint verification |
| **Git + GitHub** | Source control and collaborative development |
| **npm** | Package manager for both `backend/` and `voltwise/` workspaces |
| **ts-node** (with `--import ts-node/esm`) | TypeScript execution for the backend in development (`npm run dev`) |

## Hardware Requirements

### Server Hardware

The backend is designed to run on modest hardware suitable for a capstone/local-network deployment:

| Requirement | Minimum | Recommended |
|---|---|---|
| CPU | Dual-core 1.6 GHz | Quad-core 2.0 GHz+ |
| RAM | 2 GB | 4 GB |
| Storage | 10 GB free (OS + Node + PostgreSQL + data) | 20 GB SSD |
| Network | 100 Mbps LAN | 1 Gbps LAN |
| OS | Ubuntu 22.04 LTS / Windows 10+ / macOS 12+ | Ubuntu 22.04 LTS Server |

> For the MVP, the backend runs on a development machine (laptop/desktop) on the local network. No cloud server or public IP is required.

---

### Client Devices

| Device Type | Requirement |
|---|---|
| **Android smartphone** | Android 10 (API 29) or later; Expo Go installed, or a standalone APK build |
| **iOS smartphone** | iOS 15 or later; Expo Go installed, or a standalone IPA build |
| **Web browser (optional)** | Chrome / Firefox / Safari (latest) — Expo supports `expo start --web` for web preview |
| Screen size | 5–7 inches recommended for optimal dashboard layout |

---

### Networking

| Item | Details |
|---|---|
| Protocol | HTTP/JSON (REST) over local area network (LAN) |
| Port | Backend listens on **port 3000** (`http://localhost:3000/api` or LAN IP) |
| LAN IP resolution | `lib/api.ts` uses `expo-constants` to auto-derive the developer machine's LAN IP during development; override via `EXPO_PUBLIC_API_URL` env variable for physical devices |
| CORS | Enabled on the backend to allow requests from the Expo development client and standalone app |
| Future IoT layer | MQTT broker (planned) will connect physical sensors/MCU to the backend via a message ingestion bridge; no public internet required — operates over the same LAN |
| Internet access (development) | Required only for `npm install`, Expo CLI updates, and Prisma client generation — not for runtime app operation |
